# 项目概要设计

## 1. 项目名称
**NotionClone**（暂定）—— 一个 Web 端多合一工作区，参考 Notion 核心功能实现。

## 2. 项目目标
- 提供页面无限嵌套的块编辑器
- 支持基础数据库（表格视图优先）
- 支持多人实时协作
- 支持权限管理与分享
- 提供搜索、版本历史、模板等辅助功能

## 3. 项目范围
### MVP（第一阶段）
- 用户认证（邮箱/密码 + OAuth）
- 页面树：创建、删除、重命名、嵌套
- 块编辑器：文本、标题、列表、待办、引用、代码、图片、分割线、页面链接
- 块的拖拽、缩进、折叠、类型转换
- 斜杠命令 + Markdown 快捷输入
- 基础数据库：表格视图，支持文本、数字、单选、日期属性
- 搜索：按页面标题
- 只读分享链接

### 后续阶段
- 实时协作（多人编辑）
- 评论、提及、通知
- 数据库多视图（看板、日历）
- 高级属性（关联、汇总、公式）
- 版本历史与恢复
- 细粒度权限
- 导入/导出 Markdown、CSV
- 模板与自动化
- REST API 与第三方集成
- 离线支持（PWA）

## 4. 总体架构
系统采用前后端分离架构，包含以下核心组件：

| 组件 | 技术选型 | 职责 |
|------|---------|------|
| 前端应用 | React + Next.js + TypeScript | 用户界面、编辑器、状态管理 |
| 编辑器内核 | Tiptap / ProseMirror | 块编辑、光标选区、拖拽 |
| 协作引擎 | Yjs + y-websocket | 实时协同、冲突解决 |
| API 服务 | Go + Gin + GORM | 用户、页面、数据库、权限等业务逻辑 |
| 实时服务 | WebSocket (Socket.IO / ws) | 协作消息转发、房间管理 |
| 数据库 | PostgreSQL | 主数据存储（页面、块、数据库、用户） |
| 缓存 | Redis | 会话缓存、实时状态、发布订阅 |
| 文件存储 | S3 / MinIO | 图片、文件等二进制资源 |
| 搜索 | PostgreSQL FTS / Meilisearch | 全文搜索 |

## 5. 模块划分
### 5.1 前端模块
- **认证模块**：登录、注册、OAuth 回调
- **侧边栏模块**：页面树、工作区切换、收藏、回收站
- **编辑器模块**：块渲染、编辑交互、斜杠菜单、拖拽
- **数据库模块**：表格视图、属性编辑、排序筛选
- **协作模块**：实时同步状态、用户光标
- **搜索模块**：搜索界面与结果展示

### 5.2 后端模块
- **用户服务**：注册、登录、令牌管理
- **工作区服务**：工作区、成员、角色
- **页面服务**：页面树、页面元数据
- **块服务**：块的 CRUD、批量操作、版本控制
- **数据库服务**：数据库结构、视图、属性、行数据
- **评论服务**：评论、提及
- **搜索服务**：索引与查询
- **文件服务**：上传、下载、缩略图
- **实时协作服务**：WebSocket 连接管理、Yjs 文档持久化
- **通知服务**：站内通知、邮件通知

## 6. 关键设计决策
### 6.1 一切皆块（Block）
- 页面、文本、标题、待办、数据库等均抽象为 Block
- Block 具有统一结构：`id, type, parent_id, properties, content, position, version`
- 页面是 `type: "page"` 的 Block，数据库是 `type: "database"` 的 Block，数据库行是页面块

### 6.2 数据库抽象
- 数据库不是独立表格，而是一个 Block 集合
- 每个数据库包含多个“行页面”，每个行页面有属性
- 视图（表格、看板等）只影响展示，不改变底层数据

### 6.3 实时协作
- 采用 CRDT（Yjs）实现无冲突复制
- 每个文档（页面及其子块）对应一个 Yjs 文档
- 前端通过 WebSocket 与协作服务同步，后端持久化 Yjs 更新

### 6.4 权限模型
- 工作区级角色：Owner、Admin、Member、Guest
- 页面级权限：继承工作区，可覆盖为私有、特定成员可见
- 分享链接：生成只读或可编辑的临时令牌

## 7. 非功能需求
- **性能**：首屏加载 < 2s，块编辑响应 < 50ms，搜索 < 500ms
- **可扩展性**：后端无状态，可水平扩展；协作服务按房间分片
- **安全**：HTTPS、JWT 认证、SQL 注入防护、XSS 过滤、文件类型校验
- **可用性**：核心服务 99.9% 可用，数据每日备份

## 8. 数据流概述
1. 用户在前端编辑块 → 更新本地 Yjs 文档
2. Yjs 生成二进制更新 → 通过 WebSocket 发送到协作服务
3. 协作服务广播给同房间其他用户，并将更新写入 Redis/数据库
4. 后端 API 服务读取 PostgreSQL 获取页面结构、数据库数据
5. 搜索服务异步索引块内容
