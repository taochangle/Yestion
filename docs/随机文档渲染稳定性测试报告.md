# 随机文档渲染稳定性测试报告

## 1. 测试目的

验证 Yestion 在批量随机文档场景下，页面树、块编辑器渲染、Callout 等扩展节点，以及系统整体运行时稳定性。

## 2. 测试环境

- 前端：Next.js 16.3.1（Turbopack），运行于 `http://localhost:3100`
- API：Gin + GORM，运行于 `http://localhost:18084`
- 浏览器：Playwright Chromium Headless
- 测试账号：`theme-test-20260817@example.com`
- 测试日期：2026-08-17

## 3. 测试范围与方法

通过 API 创建独立测试工作区，并生成 30 个随机页面。随机文档覆盖以下节点类型：

- 标题 H1-H4
- 无序列表、有序列表、任务列表
- 引用块
- 代码块
- 分隔线
- 表格
- 折叠块 Details
- Callout
- 粗体、斜体、链接

使用 Playwright 依次在侧边栏点击每个页面，并监听：

- `pageerror`
- 浏览器 `console` 的 error / warning
- HTTP 4xx / 5xx 响应

复现脚本：

```bash
YESTION_AUTH_TOKEN=<token> \
python3 scripts/random_doc_stress_test.py
```

## 4. 测试结果

### 4.1 最终复测结果

| 指标 | 结果 |
| --- | --- |
| 生成页面数 | 30 |
| 实际加载页面数 | 51（包含既有页面与隔离测试页） |
| 页面运行时错误 | 0 |
| Console error / warning | 0 |
| HTTP 4xx / 5xx | 0 |
| 结论 | 通过 |

### 4.2 发现并修复的问题

首次测试中，包含 Callout 节点的页面触发：

```text
TypeError: Cannot read properties of undefined (reading 'nodeType')
```

定位结果：`Callout` 节点在 `renderHTML` 中读取了不存在的 `HTMLAttributes.emoji`，导致 ProseMirror 渲染时子节点为 `undefined`。

修复文件：

- `apps/web/lib/callout.ts`

修复提交：

```text
a4d83e4 fix: render callout emoji safely
```
